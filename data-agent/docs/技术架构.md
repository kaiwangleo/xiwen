# 析问 · 技术架构与启动

对外产品名：**析问**。仓库分两端：后端 `data-agent`，前端 `data-agent-fronted`（目录名拼写未改）。

---

## 1. 系统全景

```
浏览器 Vue3 工作台                         FastAPI :8000
 AskView / SettingsView                     /api/query          SSE 问数
                                            /api/admin/*        配置·语义·构建
                                            /api/sessions       会话整包

运行时配置           语义编辑稿              问数快照              检索引擎
conf/app_config.yaml  semantic_config        table_info           Qdrant 字段/指标
prompts/*.prompt      （元库 JSON）          column_info          ES 枚举取值
                      只保存不自动构建       metric_info          数仓 dw 跑 SQL
```

依赖（`docker-compose.yaml`）：

| 服务 | 端口 | 作用 |
|---|---|---|
| MySQL 8 | 3306 | 元库 `meta` + 数仓 `dw`（同实例两库） |
| Qdrant | 6333 | 字段 / 指标向量召回 |
| Elasticsearch + IK | 9200 | 字段枚举全文对齐 |
| 本地 Embedding | 8081 | `bge-large-zh-v1.5`，维度 1024 |
| LLM | 外网 OpenAI 兼容接口 | 扩词、过滤、生成/校正 SQL |

## 2. 概念分层（不要混）

| 角色 | 内部名 | 落点 | 说明 |
|---|---|---|---|
| 运行时配置 | `AppConfig` / `settings_service` | `conf/app_config.yaml` | 连接、阈值、UI、构建开关；`PUT /api/admin/config` 热加载 |
| 语义编辑稿 | `SemanticConfig` / `semantic_service` | 表 `semantic_config` | 勾选表/字段/指标；**只保存不自动构建** |
| 构建后快照 | `TableInfo` / `ColumnInfo` / `MetricInfo` | 表 `table_info` 等 | 问数图真正读的知识 |
| 问数图 | LangGraph `graph` | `app/agent/` | 边固定，不在运行时改 |
| 连接生命周期 | `*Manager` | `app/clients/` | 启动 init，配置变更热重载 |

HTTP 路径仍用 `/meta-config`，MySQL 表名不改。

## 4. 问数链路

意图：业务关键词优先走问数；整句寒暄才回「我是析问…」。前端 `src/utils/intent.js` 再短路一次，逻辑与后端重复。

```
extract_keywords
    ⇉ recall_column（Qdrant）
    ⇉ recall_value  （ES + IK）
    ⇉ recall_metric （Qdrant）
        → merge_retrieved_info
            ⇉ filter_table
            ⇉ filter_metric
                → add_extra_context（方言 / 当天日期）
                → generate_sql
                → validate_sql
                    ⇢ execute_sql     （校验过）
                    ⇢ correct_sql → execute_sql
```

`POST /api/query` 返回 SSE：`progress` / `result` / `error` / `chat`。

## 5. 语义层 → 检索层

设置页「语义与检索」两个 tab：

1. **语义层**：从 `information_schema` 勾表/度量，写描述别名 → `PUT /api/admin/meta-config` → 只写 `semantic_config`
2. **检索层**：`POST /api/admin/knowledge/build` SSE，6 步 id 固定：

| step | 做什么 |
|---|---|
| `load_config` | 读语义稿 |
| `save_tables` | 覆盖写 `table_info` / `column_info`，取样例 |
| `index_columns` | 字段名/描述/别名 → Qdrant |
| `index_values` | `sync` 打开的枚举 → ES |
| `save_metrics` | 指标 + 关联字段 |
| `index_metrics` | 指标向量 → Qdrant |

失败策略 `abort` / `continue`。构建会话在 runner 内打开，避免请求级 Depends 提前占连接。

## 9. 启动

### 9.1 基础设施

Embedding 镜像依赖本地模型目录 `docker/embedding/models/bge-large-zh-v1.5`（体积大，不要提交）。

```bash
cd D:/agent-project/data-agent
docker compose up -d
```

就绪检查：

- MySQL `3306`，库 `meta` / `dw`（init 脚本会建演示维表/事实表）
- Qdrant `6333`
- ES `9200`
- Embedding `http://localhost:8081/embed`

### 9.2 后端

Python ≥ 3.12。本机已有 `.venv`：

```bash
cd D:/agent-project/data-agent
.venv/Scripts/python.exe -m pip install -e .
.venv/Scripts/python.exe main.py
# 或
.venv/Scripts/python.exe -m uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

默认读 `conf/app_config.yaml`：`db_*` / `qdrant` / `es` / `embedding` 已指向本机 compose。**LLM 的 `base_url` / `api_key` / `model_name` 必须在设置页或 YAML 里配好**，否则扩词和 SQL 生成会失败。不要把密钥提交进仓库。

### 9.3 前端

```bash
cd D:/agent-project/data-agent-fronted
npm install
npm run dev
```

浏览器打开 Vite 地址（一般 `http://localhost:5173`）。

### 9.4 第一次能问数

1. 设置 → 模型与检索：确认 LLM / Embedding / Qdrant / ES / 元库
2. 数据源：指向 `dw`
3. 语义与检索 → **语义层**：勾表/指标 → 保存语义
4. **检索层**：保存参数并构建，6 步全绿
5. 回问数页，例如：「统计去年各地区的销售总额」

离线构建（可选）：

```bash
cd D:/agent-project/data-agent
.venv/Scripts/python.exe -m app.scripts.build_meta_knowledge
```
